# Модель оценки риска оттока - спецификация

Документ описывает модель целиком: от факторов кейса до итоговой формулы. Значения весов, порогов и горизонта совпадают с ТЗ ([tz/00-common.md](tz/00-common.md), раздел 6). Денежная оценка в этот документ не входит, она описана в ТЗ, раздел 6.4.

Пометки: **Факт** - из кейса или тестовых данных; **Решение** - выбор команды; **ВЭ-N** - вопрос к экспертам из ТЗ, раздел 10.

## 1. Цепочка: от фактора к оценке

```
Фактор (что говорит кейс)
   -> Признак (проверяемое условие на полях данных)
      -> Сила f (насколько выражен у услуги, 0..1, формула)
      -> Вес w (насколько важен, 0..100, настройка)
         -> Вклад = w × f
            -> Score услуги = min(100, сумма вкладов)
               -> Score клиента = max по услугам
                  -> Уровень риска (low / medium / high / none)
```

- **Фактор** - описание ситуации риска словами.
- **Признак** - тот же фактор, переведенный в условие на конкретных полях, которое можно вычислить.
- **Сила** - вычисляется из данных при каждом расчете, у каждой услуги своя.
- **Вес** - один для всех клиентов, задается командой, меняется в настройках.

## 2. Исходные данные

### 2.1 Поля, участвующие в расчете

| Сущность | Поле | Тип и единицы | Где используется |
|---|---|---|---|
| accounts | id | целое | Связь с услугами |
| accounts | balance | евроценты | доступно (F2, F4) |
| accounts | bonusBalance | евроценты | доступно (F2, F4), если bonusState = unlocked |
| accounts | bonusState | locked / unlocked | Разрешает учет bonusBalance |
| accounts | withdrawBalance | евроценты | По умолчанию не используется (ВЭ-3) |
| services | ownerId | целое | Связь услуги с клиентом |
| services | status | active, suspended, prolong\_wait, deleted, blocked | Отбор живых услуг, F1, F3, F4, F5 |
| services | autoProlong | boolean | F1 |
| services | expiresAt | дата UTC | дни до окончания (F1, F2) |
| services | price | евроценты за один период (открытый вопрос 1 ТЗ) | нужно (F2, F4) |

### 2.2 Поля, которые в расчете риска не участвуют

| Поле | Почему |
|---|---|
| services.name | Произвольное название (Факт), смысловой нагрузки нет. Используется только в тексте объяснения |
| services.paymentTerm | Напрямую не участвует. Влияет косвенно: expiresAt = createdAt + один период (Факт, генератор данных). Используется в денежной оценке |
| services.createdAt | Не нужен для текущих признаков |
| accounts.email | Идентификация в интерфейсе |
| accounts.totalReplenished | Отображается в рейтинге (Факт: обязательный столбец), в риск не входит (Решение) |
| transactions.\* | Даты не отражают реальную историю платежей (Факт, разбор данных). Возможный признак F6 - вне базового набора |

### 2.3 Параметры расчета (из настроек модели)

| Параметр | Обозначение | По умолчанию |
|---|---|---|
| Дата расчета | now | Текущее время UTC, для демо можно зафиксировать |
| Горизонт прогноза, дней | H | 7 |
| Веса признаков | w1..w5 | 50, 40, 70, 30, 15 |
| Порог среднего уровня | T\_medium | 40 |
| Порог высокого уровня | T\_high | 70 |

## 3. Промежуточные величины

Вычисляются до признаков, используются в нескольких формулах.

| Величина | Формула | Уровень | Пример |
|---|---|---|---|
| Живые услуги | LIVE = услуги клиента со status в {active, suspended, prolong\_wait} | клиент | У клиента 3 удаленных услуги: LIVE пусто |
| Дни до окончания | дни(s) = (s.expiresAt - now) / 24 ч | услуга | Истекает через 30 мин: 0.0208. Истекла 40 дней назад: -40 |
| Доступно | доступно = balance + (bonusState = unlocked ? bonusBalance : 0) | клиент | balance 83 810, bonus locked: 83 810 |
| Нужно | нужно = Σ price(s) по s из LIVE, где дни(s) <= H | клиент | Истекает одна услуга за 95: 95 |
| Общая доля нехватки (для сводки) | нужно > 0 ? max(0, 1 - доступно / нужно) : 0 | клиент | 83 810 / 95: 0. Баланс 0: 1 |
| Доля нехватки услуги | нехватка(s) = price(s) > 0 ? max(0, price(s) - fundsBefore(s)) / price(s) : 0 | услуга | Остаток 200 при цене 800: 0.75 |

Модель `expert-f1-f5-v3` распределяет общий баланс по возрастанию `expiresAt`, затем ID.
Полностью покрытое продление уменьшает остаток на свою цену. Неуспешное продление
остаток не расходует; следующая более дешёвая услуга может быть покрыта.
F2/F4 используют долю нехватки услуги на её шаге очереди.

Почему "нужно" включает уже истекшие услуги (дни < 0): их продление тоже предстоит оплатить, и в тестовых данных такие услуги есть (Факт: статусы не согласованы с датами).

## 4. Факторы и признаки

### 4.1 Сводная таблица

| Фактор | Источник фактора | Признаки |
|---|---|---|
| Ф1. Услуга скоро заканчивается, автопродление отключено | Факт: кейс, пример ситуации риска | F1 |
| Ф2. На аккаунте недостаточно средств для ближайших продлений | Факт: кейс, пример ситуации риска | F2 |
| Ф3. Услуга в статусе prolong\_wait, особенно при отсутствии средств | Факт: кейс, пример ситуации риска | F3 (сам статус), F4 (усилитель "особенно при отсутствии средств") |
| Ф4. Услуга выключена клиентом (suspended) | Решение: описание статуса в кейсе, кейс не называет его сигналом риска | F5 |

Фактор 3 разбит на два признака, потому что в нем две части: сам статус и усиление при нехватке денег. Так каждую часть можно взвесить и объяснить отдельно.

### 4.2 F1. Скоро истекает без автопродления

| Пункт | Значение |
|---|---|
| Фактор | Ф1 |
| Данные | services.status, services.autoProlong, services.expiresAt |
| Условие применения | status в {active, suspended} И autoProlong = false И дни(s) <= H |
| Формула силы | f1 = 1 - max(0, дни(s)) / H |
| Вес | w1 = 50 |
| Текст объяснения | "Услуга {name} истекает через {N} дн., автопродление выключено" или "срок истек, статус не обновлен" |

Как работает сила: линейно растет от 0 до 1 по мере приближения даты окончания.

| До окончания | Расчет | f1 | Вклад 50 × f1 |
|---|---|---|---|
| 7 дней | 1 - 7 / 7 | 0 | 0 |
| 3.5 дня | 1 - 3.5 / 7 | 0.5 | 25 |
| 30 минут | 1 - 0.0208 / 7 | 0.997 | 49.9 |
| Истекла (дни < 0) | 1 - 0 / 7 | 1 | 50 |

Почему prolong\_wait не входит в F1: услуга уже истекла и ждет оплаты, это покрывает F3.

### 4.3 F2. Не хватает средств на продления

| Пункт | Значение |
|---|---|
| Фактор | Ф2 |
| Данные | accounts.balance, accounts.bonusBalance, accounts.bonusState, services.price, services.expiresAt, services.status |
| Условие применения | status = active/suspended и дни(s) <= H |
| Формула силы | f2(s) = нехватка(s) |
| Вес | w2 = 40 |
| Текст объяснения | "Перед продлением услуги доступно {fundsBefore}; цена {price}, не хватает {shortfall} евроцентов" |

Деньги общие для клиента, но сила вычисляется отдельно для каждой услуги после предыдущих продлений.

| Остаток перед услугой | Цена услуги | Расчет | f2 | Вклад 40 × f2 |
|---|---|---|---|---|
| 1 000 | 800 | max(0, 800 - 1000) / 800 | 0 | 0 |
| 200 | 800 | (800 - 200) / 800 | 0.75 | 30 |
| 0 | 800 | 800 / 800 | 1 | 40 |

### 4.4 F3. Ожидает оплаты

| Пункт | Значение |
|---|---|
| Фактор | Ф3, основная часть |
| Данные | services.status, services.expiresAt (для даты удаления в тексте) |
| Условие применения | status = prolong\_wait |
| Формула силы | f3 = 1 |
| Вес | w3 = 70 |
| Текст объяснения | "Услуга {name} ожидает оплаты, будет удалена {expiresAt + 5 дней}" |

Сила бинарная: статус либо есть, либо нет. Дата удаления = expiresAt + 5 дней (Факт: prolong\_wait держится 5 дней). Возможное развитие: сила растет к дате удаления, но в тестовых данных все prolong\_wait просрочены, поэтому базово f3 = 1.

### 4.5 F4. Ожидает оплаты без средств

| Пункт | Значение |
|---|---|
| Фактор | Ф3, часть "особенно при отсутствии средств" |
| Данные | Как F3 + как F2 |
| Условие применения | status = prolong\_wait и дни(s) <= H |
| Формула силы | f4(s) = нехватка(s) (та же величина, что f2(s), только услуги в горизонте) |
| Вес | w4 = 30 |
| Текст объяснения | "Услуга {name} ожидает оплаты, а средств на счете не хватает" |

Для prolong_wait нехватку отражает только F4; F2 неприменим. Поэтому одна и та же
нехватка не учитывается дважды: score = min(100, w3 + w4 × нехватка(s)).

### 4.6 F5. Выключена клиентом

| Пункт | Значение |
|---|---|
| Фактор | Ф4 (гипотеза команды) |
| Данные | services.status |
| Условие применения | status = suspended |
| Формула силы | f5 = 1 |
| Вес | w5 = 15 |
| Текст объяснения | "Услуга {name} выключена клиентом" |

Обоснование: по кейсу деньги за suspended продолжают списываться, но клиент сервером не пользуется. Это слабый сигнал, что услуга не нужна.

## 5. Веса: как определяются

### 5.1 Почему нет формулы веса

Вес в моделях машинного обучения вычисляется из истории ("были такие признаки - клиент ушел"). В тестовых данных истории изменения статусов нет (Факт), поэтому вес задается командой. Источник исторических данных - ВЭ-2.

### 5.2 Метод: якорные правила -> неравенства

Каждое бизнес-правило "в такой ситуации должен быть такой уровень" превращается в неравенство на веса. Веса подбираются так, чтобы все неравенства выполнялись.

| № | Якорное правило | Неравенство | Значение |
|---|---|---|---|
| 1 | Услуга в prolong\_wait - высокий риск | w3 × 1 >= T\_high = 70 | w3 = 70 |
| 2 | Полная нехватка средств сама по себе - средний, но не высокий | T\_medium <= w2 × 1 < T\_high, то есть 40 <= w2 < 70 | w2 = 40 |
| 3 | prolong\_wait без денег - максимальный риск 100 | w3 + w4 >= 100 | w4 = 100 - 70 = 30 |
| 4 | Услуга истекает в ближайшие часы без автопродления - минимум средний | w1 × f1 >= 40 при f1 ≈ 0.99, плюс запас | w1 = 50 |
| 5 | Только suspended - низкий риск | w5 < T\_medium = 40 | w5 = 15 |
| 6 | suspended и истекла без автопродления - средний, не высокий | 40 <= w1 + w5 < 70 | 50 + 15 = 65, выполняется |

Проверка правил на тестовых данных - раздел 7.

### 5.3 Изменение весов

Веса редактируются в панели (Факт: требование кейса). Если маркетолог поменяет вес, правило может перестать выполняться. Это допустимо: настройка нужна, чтобы бизнес откалибровал модель под свое понимание риска.

## 6. Итоговая формула оценки риска

### 6.1 Score услуги

```
score(s) = min(100, Σ_i  w_i × f_i(s))     i = F1..F5, только примененные к услуге s
```

Если условие применения признака не выполнено, его f = 0 и вклад 0.

В развернутом виде:

```
score(s) = min(100,
      50 × f1(s)    [active или suspended, autoProlong = false, дни <= 7]
    + 40 × f2(s)    [active или suspended, дни <= 7]
    + 70 × 1        [status = prolong_wait]
    + 30 × f2(s)    [status = prolong_wait, дни <= 7]
    + 15 × 1        [status = suspended]
)
```

### 6.2 Score клиента

```
если LIVE пусто:
    score = нет оценки, уровень = none
иначе:
    score(клиент) = max( score(s) для s из LIVE )
```

Почему максимум: "клиенту нужно внимание, если хоть одна его услуга под угрозой". Альтернативы (среднее, взвешенное по цене) - в [churn-case-breakdown.md](churn-case-breakdown.md), раздел 5.2.

### 6.3 Уровень и лояльность

```
уровень = none,    если LIVE пусто
          high,    если score >= 70
          medium,  если 40 <= score < 70
          low,     если score < 40

лояльность = 100 - score    (Факт: кейс допускает обратную шкалу)
```

### 6.4 Объяснение

Объяснение клиента = все примененные признаки по его живым услугам с вкладом > 0, по убыванию вклада. Каждая строка: текст признака + "+{вклад} баллов".

### 7.1 Пошагово: клиент 1

1. Данные: balance = 83 810, bonusState = locked. Услуги: service-0001 (active, autoProlong = false, expiresAt 15:30, price 95), service-0011 (active, autoProlong = true, через 182 дня), service-0021 (active, autoProlong = false, через 31 день).
2. Дни: 0.0208; 182; 31.
3. доступно = 83 810. нужно = 95 (только service-0001 в горизонте). нехватка = max(0, 1 - 83 810 / 95) = 0.
4. service-0001: F1 применяется, f1 = 1 - 0.0208 / 7 = 0.997, вклад 49.9. F2: 40 × 0 = 0. score = 49.9.
5. service-0011: F1 не применяется (автопродление включено), дни > 7. score = 0.
6. service-0021: дни 31 > 7, ничего не применяется. score = 0.
7. score клиента = max(49.9; 0; 0) = 49.9 -> medium, лояльность 50.1.

### 7.2 Пошагово: клиент 5 при обнулении баланса

1. Данные: balance = 0, bonusState = locked. Услуги 5, 15, 25 в prolong\_wait, price 748, 297, 651, все истекли.
2. доступно = 0. нужно = 748 + 297 + 651 = 1 696. нехватка = 1 - 0 / 1 696 = 1.
3. По каждой услуге: F3 = 70 × 1 = 70, F2 неприменим, F4 = 30 × 1 = 30. Сумма 100.
4. score клиента = 100 -> high. Объяснение: "ожидает оплаты +70", "ожидает оплаты без средств +30".

### 7.3 Финансовая экспозиция

Для живых услуг со средним/высоким риском и сроком в горизонте рассчитываются
платежи за горизонт (внутреннее значение) и нормализованный месячный убыток
(`potentialMonthlyLoss`, единственный публичный показатель экспозиции).
Полная семантика календаря, просроченных услуг и округления описана в
[risk-engine.md](risk-engine.md). Экспозиция не меняет score и не резервирует баланс.

## 8. Как добавить новый признак

1. Описать фактор словами и источник (кейс, статус, гипотеза).
2. Выбрать поля данных.
3. Задать условие применения.
4. Задать формулу силы 0..1.
5. Сформулировать якорное правило и вывести из него ограничение на вес.
6. Написать текст объяснения.
7. Реализовать модулем и зарегистрировать (ТЗ бэкенд, раздел 3.1).
